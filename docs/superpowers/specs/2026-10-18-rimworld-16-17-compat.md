# 天赋图书馆 RimWorld 1.6/1.7 兼容性修复规格

## 目标

修复天赋图书馆在 RimWorld 1.7 启动时 Harmony 补丁绑定失败的问题，并在验证后将 Mod 元数据声明为同时支持 RimWorld 1.6 和 1.7。保留现有玩法、经验计算和存档行为。

## 已确认的问题

- 当前仓库只在 `About/About.xml` 中声明支持 RimWorld 1.6。
- 1.7 实际游戏日志显示，`Pawn_SkillTracker.Learn` 的技能参数名为 `sDef`；`Patch_NoExtraIntellectual.Prefix` 以 Harmony 命名参数 `s` 绑定目标参数，Harmony 3 因找不到名为 `s` 的目标参数而在 `TalentLibrary.Startup` 的补丁初始化期间报错。
- 这是参数名绑定不一致导致的初始化错误，不是学习经验规则本身的失败。修复应避免依赖目标方法的参数名。

## 设计

- 将该 Prefix 改为 Harmony 的位置参数绑定（`__0`、`__1`），维持原有参数顺序、类型、前置条件和返回值语义。
- 在 1.7 隔离启动验证通过后，把 `1.7` 加入 `About/About.xml` 的 `supportedVersions`；保留 `1.6`。
- 保持单份共享 DLL。只有在验证发现 1.6/1.7 存在其他不可兼容 API 时，才重新评估是否需要版本专用程序集。
- 更新用户文档中的版本支持描述，使其与元数据一致。

## 范围

本次只处理已定位的 Harmony 参数绑定启动错误及双版本支持声明。若隔离启动发现其他由本 Mod 引起的加载错误，继续追溯并修复完成双版本启动所必需的问题。

不改变阅读、写作、技能经验、书籍效果或 Def 平衡；不处理其他 Mod 的报错；不将未在隔离日志中复现的问题归因于本 Mod。

## 验收条件

1. 共享 DLL 可使用仓库当前的 RimWorld 1.6 参考程序集构建，且代码未引入仅 1.7 存在的 API。
2. 现有 34 项核心规则断言通过，XML/Def 静态验证通过。
3. 使用 Core、Harmony、Talent Library 的隔离 RimWorld 1.7 配置启动后，不再出现本 Mod 的 `Startup`/Harmony 补丁初始化错误；检查完整启动日志中的本 Mod 错误。
4. `About/About.xml` 声明支持 1.6 与 1.7，文档与之相符。
5. 结果如实区分自动化检查和游戏内实测；本机没有 1.6 游戏环境时，不声称完成 1.6 实机启动验证。
